## 1. Law 4 — SUM(lines) == header guard (V280) — NEW, LIVE
- **Problem:** `je_balanced` CHECK asserts only `total_debit == total_credit` (header vs header).
  NOTHING asserted `SUM(journal_lines) == journal_entries.total_*`. A POSTED journal could
  persist lines that don't sum to its header (real: BP-2608-0001 lost Rp2.500). 94 DRAFT→POSTED
  paths, no central kernel.
- **Fix:** `V280__journal_line_header_balance_guard.sql` — `guard_journal_line_header_balance()`
  + two **DEFERRABLE INITIALLY DEFERRED** constraint triggers (`trg_journal_line_header_balance_lines`
  on journal_lines INS/UPD/DEL, `trg_journal_line_header_balance_header` on journal_entries INS/UPD).
- **Semantics:** POSTED only (DRAFT/VOID skipped), tolerance 0.01. Deferred → checks FINAL committed
  state, so the Law-20 `DRAFT → insert lines → UPDATE POSTED` sequence is never checked mid-flight.
  Rejection message names the `journal_number` and both sums (diagnosable from the error alone).
- **Does NOT block the 94 paths:** deferred design tolerates any Law-20-compliant path. Only a path
  that commits a POSTED header in a txn SEPARATE from (before) its lines would break — Law-20-violating,
  and the full-tenant audit shows zero such data.
- **Verified:** audit = 0 mismatches all tenants (no backfill). 2-sided gate (real grapgrap
  DRAFT→POSTED journal, `SET CONSTRAINTS ALL IMMEDIATE`, rolled back): GREEN balanced accepted, RED
  header+100 rejected with named message. Post-deploy: audit still 0; a REAL manual journal posted
  + reversed through the app kernel (`journals.create_journal` / `reverse_journal`) — both committed
  through the live trigger.
